**Why it's split this way**

- `shared/Game` is **hybrid game code with no Roblox dependencies** (plain-data state, strategy classes for varying behavior, function modules for the rest), so it can be
  tested outside Studio and reused by the server, bots, and tests. It must
  not require anything from `server/` or `client/`.
- `shared/Config` is **data only**. Balance changes should never require
  touching logic files.
- `shared/Net` is the **single contract** between client and server. Both
  sides import payload types from here so they can't drift apart.
- `server/` is the **authority**. It validates intents, runs the round
  engine, and decides what each player is allowed to see.
- `client/` is **presentation and input only**. It renders from replicated
  state and sends intents; it never decides game outcomes.

**Dependency direction (never reverse these)**

```
client  --->  shared  <---  server
              (Game, Config, Net)
```

`client` and `server` must never require each other. `shared/Game` must never
require Roblox services. If you find yourself wanting to break one of these,
stop and ask.

**Where new things go (rule of thumb)**

| If you're adding... | Put it in |
|---|---|
| A rule, formula, or resolution step | `shared/Game` (+ a test) |
| A tunable number, new policy, new class stat | `shared/Config` |
| A new client-to-server action or server-to-client message | `shared/Net` first, then handler/consumer |
| Validation, timers, match flow, bot behavior | `server/Services` |
| A screen, panel, or widget | `client/UI` |
| Something that animates the city | `client/City` |
